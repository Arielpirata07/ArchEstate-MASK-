# Deploy — Railway (app) + Supabase (Postgres)

> Estado: plan de referencia, no ejecutado. Reemplaza `render.yaml` + `.plans/deploy-checklist.md` (Render).
> Versión base: v0.33.0. App: Flask factory (`factory.py:create_app()`), entry `wsgi:app`.

## Arquitectura objetivo

- **App**: Railway Web Service (nixpacks, Python) — `gunicorn wsgi:app --bind 0.0.0.0:$PORT`.
- **DB**: Supabase Postgres — la app usa el pooler (puerto 6543, PgBouncer); migraciones manuales con conexión directa (5432).
- **Rate limiting**: Redis (plugin de Railway, `REDIS_URL`), fallback a archivo en local.
- **Uploads**: Supabase Storage (buckets `avatars`, `docs`). Railway es efímero: `static/uploads/` se pierde en cada redeploy.

## Por qué no alcanza con cambiar env vars

1. `app_setup.py:102-536` es SQLite-only: `INTEGER PRIMARY KEY AUTOINCREMENT`, `PRAGMA table_info`,
   `ALTER TABLE` sin `IF NOT EXISTS`. En Postgres falla al primer boot (`init_db`).
   El DML es portable (`?` → `%s` en `services/database.py:64-69`); el DDL no.
2. `config.py:14` + `services/database.py:132-136,183` solo aceptan `postgresql://`.
   Supabase entrega `postgresql://...?sslmode=require` (pooler 6543) — aceptar query string y SSL.
3. `rate_limit.py:21` guarda JSON en tmp: no comparte entre workers/réplicas, se pierde en Railway.
4. `wsgi.py` no lee `$PORT`; Railway lo exige para el bind.

## Cambios de código requeridos

### 1. Compat DDL (`app_setup.py`)
- `AUTOINCREMENT` → `GENERATED BY DEFAULT AS IDENTITY` cuando driver = postgresql.
- `PRAGMA table_info(t)` → `table_columns(t)` (`services/database.py:155`, ya portable vía `information_schema`).
- `ALTER TABLE x ADD COLUMN ...` → `ADD COLUMN IF NOT EXISTS ...`.
- `DATETIME DEFAULT CURRENT_TIMESTAMP` → `TIMESTAMPTZ DEFAULT NOW()`.
- `CREATE INDEX IF NOT EXISTS` ya es válido en Postgres, se conserva.

### 2. Conexión (`config.py`, `services/database.py`)
- Aceptar `postgresql://` y `postgres://`, conservar `?sslmode=require` al conectar con psycopg2.
- `psycopg2-binary` ya está en `requirements.txt:10`. Con PgBouncer (pooler): `autocommit = False` actual sirve;
  evitar prepared statements con nombre si se migra a `psycopg` v3 en el futuro.

### 3. Railway (`railway.toml` nuevo, archivar `render.yaml`)
```toml
[build]
builder = "nixpacks"
buildCommand = "pip install -r requirements.txt"

[deploy]
startCommand = "gunicorn wsgi:app --bind 0.0.0.0:$PORT --workers 2 --timeout 120 --access-logfile - --error-logfile -"
healthcheckPath = "/health"
healthcheckTimeout = 120
restartPolicyType = "on_failure"
```

### 4. Rate limiting (`rate_limit.py`)
- Backend Redis cuando `REDIS_URL` está seteada (clave por IP + ventana, `SET ... EX NX` / sorted sets).
- Fallback a JSON actual cuando no hay `REDIS_URL` (local/dev).
- Actualizar docstring (hoy dice "pendiente migrar a Redis (Render KV)").

### 5. Uploads (`config.py:21-22`, `factory.py:31-32`, `routes_profile.py`)
- Subir a Supabase Storage en prod; servir por URL pública/firmada.
- Alternativa mínima: volumen Railway (solo 1 réplica). Sin una de las dos, avatares/docs se pierden.

## Migración de datos (solo si `database.db` tiene datos que conservar)

1. Crear proyecto Supabase, anotar URLs pooler (6543) y directa (5432).
2. Boot de la app contra Supabase con DB vacía → `init_db` crea schema.
3. Copiar datos SQLite → Postgres en orden FK (users → organizations → professionals → leads → resto)
   con script dedicado (mapear `INTEGER 0/1` → booleanos donde aplique, `DATETIME` → `TIMESTAMPTZ`).
4. Verificar conteos por tabla en ambos lados antes de apuntar el tráfico.

## Costos / límites (a revisar al ejecutar)

- Supabase free: 500 MB DB, Storage y bandwidth limitados — suficiente para arranque.
- Railway: sin free tier permanente; app + Redis consumen crédito. 1 réplica + volumen es lo más barato si se evita Storage al inicio.
